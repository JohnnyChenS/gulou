# 鼓楼 Agent 知识库一期改造方案

## 定位

鼓楼从“开源成长内容库”调整为“AI 成长 Agent 的公开知识底座”。产品侧先验证一个闭环：用户输入年龄、阶段、困扰和目标后，Agent 能基于知识库生成短期成长目标、可执行行动和复盘问题。

一期不追求全人生覆盖，也不做多模态记录、长期记忆和开放式聊天。先验证：

> 阶段识别 -> 4 周目标 -> 每周行动 -> 复盘评估 -> 调整建议

## 一期场景

优先场景：0-3 岁新手父母。

选择原因：

- 现有内容最完整，尤其是 0-3 岁、日常护理和父母支持。
- 用户痛点明确：哭闹、睡眠、喂养、动作发育、父母疲劳。
- 可形成低频复盘：每周记录观察，每周调整建议。

## 产品闭环

### 输入

用户首次使用时输入：

- 使用者角色：父母、照料者、学习者本人
- 被观察者年龄或用户年龄
- 当前阶段：新生儿、婴幼儿、学龄前、青春期、大学期等
- 当前困扰：睡眠、哭闹、动作、语言、情绪、学业、职业等
- 近期目标：降低焦虑、建立习惯、培养能力、改善问题
- 可投入时间：每天 5 分钟、15 分钟、30 分钟等
- 当前状态自评：1-5 分

### 输出

Agent 首次输出固定为：

1. 当前阶段判断
2. 本阶段核心成长任务
3. 未来 4 周短期目标
4. 本周最重要的 1 个行动
5. 每周观察指标
6. 不用焦虑的正常现象
7. 需要警惕的信号
8. 下次复盘问题
9. 关联知识库文章

### 复盘

每周复盘输入：

- 本周完成了哪些行动
- 哪些没有完成
- 孩子或本人出现了哪些新变化
- 当前焦虑或状态评分变化
- 新出现的问题

复盘输出：

- 本周变化总结
- 目标是否需要调整
- 下周继续、降低或升级的行动
- 是否触发警惕信号

## 知识卡字段

现有 Markdown 继续面向人阅读，但 frontmatter 增加 `agent_use`，让 Agent 可以稳定检索和组合。

```yaml
agent_use:
  primary_user: parent
  applies_to:
    age_range: 0-6m
    stage: 新生儿期
  intent_triggers:
    - 用户担心宝宝睡眠
    - 用户疲劳或崩溃
  growth_tasks:
    - 建立昼夜节律
    - 保护父母基础睡眠
  observable_signals:
    - 放下就醒
    - 夜间频繁醒来
  measurable_indicators:
    - 每天最长连续睡眠时长
    - 父母连续睡眠时长
  suggested_actions:
    - 观察清醒窗口
    - 建立夜间低刺激流程
  red_flags:
    - 呼吸异常
    - 体重增长不良
  review_questions:
    - 这周最长连续睡眠有多久？
    - 哪个夜间流程最难执行？
```

## 首批主题

### 孩子状态

- 哭闹快速排查
- 抱新生儿
- 新生儿睡眠
- 喂养实操
- 拍嗝
- 换尿不湿
- 肠胀气应对
- 安全依恋
- 粗大动作与俯卧时间
- 语言输入与回应

### 父母状态

- 睡眠剥夺
- 产后情绪
- 夫妻夜间分工
- 完美主义和比较焦虑

## GitHub 定位

GitHub 继续作为公开知识底座和信任入口，不直接承载完整产品逻辑。

公开内容：

- 发展阶段框架
- 通用知识文章
- 引用来源
- Agent 知识卡 schema
- 样例输出模板

不公开内容：

- 用户记录
- 个性化报告生成链路
- 评估权重
- Prompt 编排
- 商业化 Agent 服务逻辑

## 验证标准

一期完成后，至少能手工或半自动生成 3 份 4 周计划：

1. 0-1 月新手父母：哭闹和睡眠焦虑
2. 2-3 月宝宝：担心抬头和动作发展
3. 6-9 月宝宝：分离焦虑或睡眠倒退

每份计划必须包含：

- 阶段判断准确
- 行动足够小，父母当天可做
- 指标可观察，不依赖复杂设备
- 明确区分正常现象和警惕信号
- 能在一周后复盘并调整
