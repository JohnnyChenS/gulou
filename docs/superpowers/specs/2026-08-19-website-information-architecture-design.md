# 鼓楼知识库网站信息架构重构设计

## 背景

网站经过多轮内容扩充后，首页同时提供按人生阶段、按孩子年龄、按问题、按主题和按学习路径等入口。每个入口都能找到一部分内容，但用户需要先理解目录体系，才能判断从哪里开始。

本次重构不减少公开知识，也不把新主题做成新的并列栏目，而是恢复一条清晰的阅读主线：先判断人生阶段，再进入当前场景、孩子年龄和阶段能力，最后进入具体文章或深入路径。

## 目标

1. 让新用户从首页即可理解项目是什么、为什么存在、当前最关注什么。
2. 将首页的主要选择收敛为人生阶段，避免多个平行入口互相竞争。
3. 让家庭期用户按场景进入“育儿指导”或“父母自身支持”。
4. 让育儿指导用户先选择孩子年龄，再查看该阶段的关注点、能力主线和培养过程。
5. 将脑科学、学习能力、兴趣探索、好奇心等内容嵌入现有年龄阶段，不新增顶层入口。
6. 保留已有公开内容和旧链接，降低迁移成本。

## 非目标

- 不删除家庭期之外的未来阶段内容。
- 不把公开知识库改造成 Agent 的产品选择逻辑；MVP 内容选择仍由 `gulou-agent` 管理。
- 不在本轮建立新的内容管理系统或复杂路由抽象。
- 不把所有旧路径文章复制到新的年龄页；年龄页负责组织和指路，文章保留为深入内容。

## 新的主路径

```text
首页
└── 人生阶段
    └── 家庭期（25–45 岁）
        ├── 育儿指导（0–18 岁）
        │   └── 孩子年龄
        │       └── 阶段关注点与能力培养
        │           └── 具体文章 / 深入路径
        └── 父母自身支持
```

“按问题”和“学习路径”仍然存在，但属于辅助索引：只有在年龄页或具体文章中确实有帮助时才被引用，不再与人生阶段并列出现在首页和顶部导航。

## 首页结构

首页按以下顺序组织：

1. **项目说明**：鼓楼是什么，以及“鼓楼 = grow”的含义。
2. **项目动机**：为什么需要一个按成长阶段整理、可以逐步使用的知识库。
3. **项目规划**：从早期育儿支持逐步扩展到人的长期成长。
4. **现阶段目标**：当前优先服务 0–3 岁孩子的新手父母，帮助他们从观察问题走到下一步行动。
5. **人生阶段入口**：以人生阶段作为首页唯一的主要导航，包括家庭期和已有内容的其他阶段。
6. **参与和参考**：贡献方式、参考资料和项目仓库链接。

首页不再展示按年龄、按问题、主题路径或学习路径的并列卡片。现有“为什么叫鼓楼”内容保留在项目说明区域。

## 顶部导航

顶部导航保留：

- 首页
- 人生阶段
- 知识参考
- 参与贡献
- GitHub

移除以下并列导航项：

- 按年龄
- 按问题
- 主题路径
- 学习路径

这些内容仍可从年龄页或文章的“深入阅读”“遇到具体问题时”区域进入。

## 家庭期结构

家庭期首页首先呈现两个场景入口：

```text
家庭期
├── 育儿指导（0–18 岁）
└── 父母自身支持
```

已有的育儿年龄内容、父母睡眠与产后适应、父母学习等内容继续保留，但不再在家庭期首页用一张很长的混合表格同时展开。家庭期首页只负责说明场景和下一步选择；具体内容由下一级页面承载。

尚未有实质内容的婚姻、家庭关系、健康管理等未来场景暂不作为入口展示，待内容达到可用规模后再加入。

## 育儿指导年龄索引

新增明确的页面：

```text
stages/家庭期（25-45岁）/育儿指导/_index.md
```

该页面只做年龄选择，提供六个年龄入口：

- 0–3 岁：依恋、安全感与发展基础
- 3–6 岁：生活自理、好奇心与游戏中的学习
- 6–9 岁：学校适应、学习习惯与阅读
- 9–12 岁：自我调节、理解力与持续探索
- 12–14 岁：元认知、信息判断与青春期适应
- 14–18 岁：自主学习、兴趣项目与方向选择

## 年龄页标准结构

六个年龄页采用统一的阅读顺序，但允许保留符合年龄特点的细节。例如 0–3 岁已有的月龄照护表可以作为阶段专属内容继续存在。

每个年龄页按以下顺序组织：

1. **阶段概览**：这个阶段的主要变化和家长定位。
2. **当前关注点**：最值得优先处理的几项任务。
3. **能力培养主线**：把认知与心理、身体能力、学习与探索等内容放在同一张阶段地图中。
4. **培养过程**：将能力主线连接到日常互动、家庭活动、练习步骤和可观察行为。
5. **日常照护与家长支持**：按年龄保留照护重点，并在需要时链接父母自身支持。
6. **发展观察与风险提示**：区分正常差异、需要持续观察的信号和需要专业帮助的情况。
7. **深入阅读与参考**：链接具体文章、辅助路径和权威参考资料。

## 新主题的年龄归位

新增主题不创建新的顶层目录，而按主要适用年龄写入年龄页的能力主线和培养过程：

| 年龄段 | 归位内容 |
| --- | --- |
| 0–3 岁 | 学习基础、共同注意、早期阅读、在照护和互动中保护好奇心 |
| 3–6 岁 | 好奇心、执行功能、前阅读、兴趣尝试 |
| 6–9 岁 | 学习习惯、提问、独立阅读、创造性思考 |
| 9–12 岁 | 自我调节、提取练习、错误修正、项目式探索 |
| 12–14 岁 | 元认知、时间管理、信息判断、压力调节 |
| 14–18 岁 | 自主学习、持续兴趣、项目实践、方向选择 |

内容新增时遵循：

```text
判断适用年龄
→ 放入该年龄页的能力主线
→ 在培养过程中链接具体文章或步骤
→ 不新增首页或顶部导航入口
```

## 旧路径兼容策略

不直接删除已有路径，以避免书签和外部引用失效：

- `paths/learning/ages/` 保留为兼容页，说明内容已经并入对应年龄页，并提供规范入口。
- `paths/learning/questions/` 保留为问题索引，只作为年龄页中的辅助入口。
- `paths/0-3/` 等具体培养文章继续保留，由相应年龄页的“培养过程”或“深入阅读”引用。
- `paths/` 不再作为首页主入口，也不出现在顶部导航中。

兼容页需要明确当前规范入口，避免用户在旧路径和新年龄页之间反复跳转。已有内容只做必要的导航补充，不进行大规模复制。

## 网站实现范围

1. 调整首页渲染函数：把项目说明、动机、规划、现阶段目标放在前面，只保留人生阶段主入口。
2. 调整顶部导航：移除按年龄、按问题、主题路径和学习路径的并列链接。
3. 重写家庭期 `_index.md` 的首屏结构，先呈现场景选择，再链接具体内容。
4. 新增家庭期下的育儿指导年龄索引。
5. 按统一顺序整理六个年龄页，并把现有学习、好奇心、兴趣和脑科学相关文章接入相应阶段。
6. 为旧的年龄路径和问题路径增加规范入口提示。
7. 保留路由注册和已有内容，不手工编辑生成目录 `website/site/`。

## 验收标准

- 首页的主要入口只有人生阶段；用户不会同时看到年龄、问题和主题三套平行入口。
- 顶部导航不再出现按年龄、按问题、主题路径和学习路径。
- 家庭期首页清晰区分“育儿指导”和“父母自身支持”。
- 育儿指导页面提供六个年龄入口。
- 每个年龄页都能按“阶段概览 → 关注点 → 能力主线 → 培养过程 → 支持 → 观察 → 深入阅读”阅读。
- 学习能力、兴趣探索、好奇心和脑科学内容能从对应年龄页进入，而不是依赖新的顶层入口。
- 旧路径仍可访问，并能指向新的规范入口。
- `npm run check:routes` 通过。
- `npm run build` 通过。

## 主要风险与应对

| 风险 | 应对 |
| --- | --- |
| 首页入口减少后，旧用户找不到按问题内容 | 保留兼容页，并在年龄页提供“遇到具体问题时”的辅助链接 |
| 年龄页整理时形成新的长目录 | 每个年龄页只展示阶段主线，具体知识下沉到文章和深入阅读 |
| 六个年龄页结构过度模板化 | 统一阅读顺序，不强制所有年龄使用完全相同的表格；保留 0–3 岁月龄细节 |
| 新主题再次形成目录膨胀 | 将“适用年龄”作为新增内容的必要归位步骤，并把验收标准写入路由检查和内容审阅 |
| 公开知识被误删以追求 MVP 聚焦 | 只调整网站组织方式；Agent 的 MVP 选择继续由 `gulou-agent` manifest 控制 |
