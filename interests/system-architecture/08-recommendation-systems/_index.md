# Recommendation Systems

## 阶段目标

把可服务的模型组合成从候选生成到实验反馈的线上推荐链路。完成后，你应能解释某个内容为什么进入候选、如何被排序和重排，以及用户行为如何回到数据与模型；还能识别冷启动、反馈回路和实验偏差何时使结论失效。

## 进入条件

本阶段继承 ML Systems 的特征/标签、数据切分、泄漏检查、模型服务、版本、漂移与回滚契约，并继续遵守 SRE 的 SLO 与降级边界。本阶段不承诺覆盖所有推荐算法，也不承诺点击率提升就代表用户价值、公平性或长期效果改善。

## 这一阶段先把什么讲清楚

- **候选生成（召回）**从巨大内容集合中快速找出数量可控的候选，目标是用可接受的延迟保留可能有价值的项目；未被召回的内容不会进入后续阶段。
- **排序**使用更丰富的用户、内容和上下文特征预测候选价值，通常比召回更慢、但判断更精细。
- **重排**在最终列表上合并多目标、多样性、新鲜度、安全、去重和业务规则，它暴露的是产品取舍，不只是模型分数。
- **反馈回路**把曝光、点击、停留、跳过等行为返回特征、标签和评估。系统只能学到它曾经展示并且记录下来的结果，因此当前策略会改变未来训练数据。
- **冷启动**指新用户、新内容或新场景缺少历史行为。需要用内容特征、热门或编辑先验、明确探索和安全兜底获取信号，不能把“没有行为”解释为“没有兴趣”。
- **实验偏差**来自曝光选择、分流污染、指标延迟、新鲜感、幸存者和策略干扰。A/B 实验要预先声明实验单位、随机化方法、主指标、护栏、时长和停止规则，否则相关性不能支撑因果结论。

## 组件如何承载这些思想

候选生成可由协同过滤、内容规则、向量检索或双塔模型承载；排序服务组合实时特征与预测模型；重排服务执行多目标和硬规则；实验平台记录分流、曝光、结果和护栏。缓存和降级路径要保留可解释的版本和用户结果，不应用过期特征静默换取可用性。

## 综合项目产物

提交一张从候选生成、排序、重排到曝光和反馈回流的在线时间线，标出各阶段输入、候选数、模型/规则版本、延迟预算、缓存与降级结果。再提交冷启动策略和一份预注册实验记录，记录曝光口径、主指标、护栏、可能偏差与回滚条件。

## 阶段挑战

面对“新排序模型使点击率上升，但新内容曝光下降且长期保留指标尚未回流”的结果，分别检查召回覆盖、重排规则、冷启动、曝光偏差和实验分流。在证据不足时必须选择继续观察、降级或回滚，不得用单一点击指标宣布成功。

## 阅读顺序

先沿请求时间线理解候选生成、排序和重排，再沿数据时间线理解曝光、反馈回路与实验偏差，最后把冷启动、缓存和降级放入两条时间线。能用证据判断一次实验是否可支撑发布后，进入 AI Engineering。
