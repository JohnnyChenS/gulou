# AI 工程（AI Engineering）

## 阶段目标

在可运营、可评估的系统边界内增加生成式 AI 能力。完成后，你应能区分单次模型调用、检索增强生成、确定步骤工作流与 Agent 循环，并用评估、护栏、最小工具权限、追踪和回放证明能力的效果与安全边界。

## 进入条件

本阶段直接继承 Recommendation Systems 的候选、排序、反馈与实验偏差，并继承前面阶段的数据契约、版本、SLO、权限、发布和回滚证据。本阶段不承诺模型输出天然正确，不承诺 RAG 消除幻觉，也不把 Agent 当作无需限权、审批或停止条件的自主系统。

## 这一阶段先把什么讲清楚

- **Token 与 Context**：Token 是模型处理文本的切分单位，Context 是一次调用中可见的指令、数据、对话和工具结果。上下文窗口有限，较长输入会增加延迟和成本，也不等于模型能正确使用其中每条信息。
- **Embedding、检索与 RAG**：Embedding 把内容映射为可比较的向量，检索按查询与索引规则选出候选证据，RAG 再把证据放入生成上下文。结果依赖分块、索引、版本、权限过滤、召回与引用校验；“检索到”不等于“证据支持回答”。
- **Workflow 与 State Machine**：Workflow 把预定步骤、分支、输入输出和失败策略连接起来；State Machine 显式记录当前状态、允许的转移和恢复点。对可预见任务，这种确定边界通常比开放循环更容易测试和运营。
- **Agent Loop**：Agent 循环让模型在观察、选择下一步、调用工具和读取结果之间反复迭代。必须设置最大步数、时间/成本预算、幂等键、停止条件、人工审批点和不确定结果处理。
- **评估与护栏**：评估用版本化用例和明确判据比较正确性、引用支持、工具选择、安全、延迟和成本；护栏在输入、输出、工具和数据边界上拒绝或升级高风险行为。两者都只能降低已知风险，不能证明所有情况下安全。
- **工具权限**：每个工具都要有最小资源范围、参数校验、身份与审计记录。读取、写入、发送消息、产生费用和删除资源不应共享同一权限级别；影响外部世界或难以恢复的操作需要更强审批和补偿边界。

## 组件如何承载这些思想

模型 API 承载 Token/Context 与结构化输出契约，Embedding 模型、向量索引和检索服务承载 RAG 候选路径，工作流编排器或状态机保存可恢复步骤，工具网关执行 Schema、身份、限额与审计，评估集和追踪系统连接输入、版本、决策、工具结果和用户结果。框架 API 只是实现；边界、评估和权限契约才是本阶段的主线。

## 综合项目产物

在推荐平台中只选一项有明确用户价值的 AI 能力，提交：一张区分模型调用、检索、工作流/状态机、Agent 循环和工具边界的设计图；一份覆盖正常、缺证据、Prompt Injection、越权工具、工具失败、无限循环和模型降级的评估结果；以及权限矩阵、人工审批点、预算、追踪、回放与回滚记录。

## 阶段挑战

让一条来自检索文档的恶意指令诱导系统读取越界数据并调用有写权限的工具。沿检索、上下文组装、模型决策、工具授权、外部副作用和审计时间线，说明每层应拒绝、升级或停止什么。然后用版本化评估和回放证明修正没有破坏正常任务、SLO 与成本预算。

## 阅读顺序

先理解 Token/Context 的输入边界，再学习 Embedding、检索与 RAG 的证据链；接着先设计可控的 Workflow/State Machine，只在任务需要动态选择步骤时引入 Agent Loop。最后用评估、护栏和工具权限完成发布门禁。产物能证明效果、安全、恢复和成本边界后，返回[课程总入口](../_index.md)并进入[综合项目完成门禁](../capstone/_index.md)。
